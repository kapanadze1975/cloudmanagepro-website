How to Require Intune-Compliant Devices for Microsoft 365

A practical CloudManagePro guide for understanding how Intune device compliance and Microsoft Entra Conditional Access can work together to protect access to Microsoft 365.

Technical Guide•Intermediate•CloudManagePro
✓Compliant
Microsoft 365
🔒
About this guide This article explains how to require devices managed by Microsoft Intune to be evaluated as compliant before granting access to Microsoft 365 resources using Microsoft Entra Conditional Access. It covers what the configuration accomplishes, prerequisites and licensing, guidance for administrator roles, testing options (report-only and What If), rollout recommendations, legacy authentication considerations, troubleshooting, and best practices.

Overview

When you require Intune-compliant devices for Microsoft 365 access, Microsoft Entra Conditional Access evaluates the device compliance state reported by Microsoft Intune and enforces a grant control that requires the device to be marked as compliant before access is allowed. This integrates device compliance telemetry with access control to conditionally allow or block user sign-ins to Microsoft 365 services.

Prerequisites

  • Devices must be enrolled in Microsoft Intune and subject to Intune device compliance policies so they can be evaluated as compliant or noncompliant. See Microsoft Intune device compliance documentation: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview
  • Conditional Access policies that use device compliance rely on Microsoft Entra Conditional Access. Ensure Conditional Access is available under your Microsoft Entra licensing: https://learn.microsoft.com/en-us/entra/fundamentals/licensing
  • Users who receive Intune policies must have the required Intune licensing assigned: https://learn.microsoft.com/en-us/intune/fundamentals/licensing and https://learn.microsoft.com/en-us/intune/fundamentals/assign-licenses
  • Administrators who create and manage Intune compliance policies must have the appropriate Intune RBAC roles: https://learn.microsoft.com/en-us/intune/fundamentals/role-based-access-control/ref-built-in-roles and https://learn.microsoft.com/en-us/intune/govern-administer

Licensing

Verify both Intune licensing for managed devices and Microsoft Entra licensing for Conditional Access features before enforcing device compliance.

Administrator role guidance

Use least-privilege principles when assigning administrative roles. For Conditional Access policies the Conditional Access Administrator role is the least-privileged built-in role to manage policies. For Intune policy management, use Intune RBAC built-in roles.

Configuration

Configure Intune device compliance policies and a Conditional Access policy that uses the grant control "Require device to be marked as compliant." Follow Microsoft guidance when creating compliance policies and Conditional Access rules.

1

Prepare the pilot

Start with a pilot group of users and devices to verify enrollment and compliance evaluation before broader rollout.

2

Create compliance policy

Create and assign Intune compliance policies appropriate for your environment. See: https://learn.microsoft.com/en-us/intune/device-security/compliance/create-policy.

3

Configure Conditional Access

Create a Conditional Access policy that targets the desired users and applications and include the grant control "Require device to be marked as compliant." See: https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-grant.

Rollout recommendations

  • Start with report-only analysis and the What If tool to identify potential impact on users and applications.
  • Gradually scope enforcement (for example, pilot groups) to reduce risk before broad rollout.
  • Ensure Intune compliance policies are in place and that devices in pilot groups are enrolled and receiving compliance evaluations.

Legacy authentication considerations

Identify and address legacy authentication, which can bypass Conditional Access protections. See guidance on blocking legacy authentication and monitoring legacy auth activity.

Testing & validation

Use Conditional Access report-only mode and the What If tool to understand policy impact and simulate outcomes before enforcement.

Report-only guidance: https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-report-only

What If tool: https://learn.microsoft.com/en-us/entra/identity/conditional-access/what-if-tool

Troubleshooting

  • Confirm devices are enrolled in Intune and receiving compliance policy evaluation: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview
  • Verify applicable users are assigned the required Intune licenses: https://learn.microsoft.com/en-us/intune/fundamentals/licensing
  • Confirm Conditional Access is available and licensed for your tenant: https://learn.microsoft.com/en-us/entra/fundamentals/licensing
  • Use report-only mode and the What If tool to analyze policy effects and diagnose unexpected behavior.

Best practices

  • Validate policies in report-only mode and with the What If tool before enforcement.
  • Use least-privilege administrative roles; assign Intune and Conditional Access roles according to organizational governance.
  • Plan a phased rollout and ensure licensing requirements for both Intune and Conditional Access are met before broad enforcement.
  • Monitor and address legacy authentication to ensure Conditional Access policies are effective.

FAQ

Can Conditional Access use Intune compliance state?

Yes. Microsoft Intune device compliance status can be used by Microsoft Entra Conditional Access as a signal for policy evaluation. See: https://learn.microsoft.com/en-us/intune/device-security/conditional-access-integration/overview

Which grant control enforces Intune device compliance?

Microsoft Entra Conditional Access includes the grant control "Require device to be marked as compliant." See: https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-grant

Do users need Intune licenses to be evaluated as compliant?

Yes. Microsoft Intune licensing is required for users receiving applicable Intune policies. See: https://learn.microsoft.com/en-us/intune/fundamentals/licensing
